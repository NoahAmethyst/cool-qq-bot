# 每日经济总结纯文本输出设计

## 背景与目标

每日 23:56 的经济总结由 Jarvis 生成，并按固定四章发送到 QQ 群聊和私聊。QQ 消息不以 Markdown 渲染，因此总结正文统一使用适合 QQ 直接阅读的普通文本；允许使用 emoji 和符号表情突出章节、重点信息、风险和机会。

本次变更只调整每日经济总结的输出约定与发送前兜底处理，不改变新闻采集、Jarvis 知识库、四章 marker 协议、订阅状态、调度时间或消息长度限制。

## 方案选择

采用“提示词约束 + 发送前清理”的双重保障：

1. 在每日经济总结提示词中明确要求返回普通文本，禁止 Markdown 标题、列表标记、强调、删除线、代码块、表格、引用和 Markdown 链接。
2. 提示词允许使用 emoji 和普通符号强化标题、重要结论、风险与机会。
3. Jarvis 返回内容完成四章 marker 解析后，对每章正文执行轻量 Markdown 清理，再进入既有分段和发送流程。

相比仅修改提示词，该方案能处理模型偶尔不遵守格式约定的情况。相比引入完整 Markdown 解析器，该方案不增加依赖，且与现有天气推送的 QQ 纯文本需求一致。

## 代码设计

将 `coolq/weather.go` 中现有的 Markdown 清理规则整理为 `coolq` 包内可复用的纯文本转换函数。天气推送继续调用该函数，经济总结在四章解析成功后也调用同一函数。

经济总结处理流程如下：

1. 构造包含纯文本约束的 Jarvis 总结提示词。
2. 调用 Jarvis Summary，并按既有协议解析四个 chapter marker。
3. 对四章正文逐章转换为 QQ 普通文本，保留 emoji、中文标点、自然段和普通符号。
4. 任意章节转换后为空，整次总结视为失败，沿用现有总结失败通知，不发送不完整内容。
5. 转换成功后，沿用既有固定章节标题、1000 字符分段、低置信度提示和群聊/私聊扇出逻辑。

清理逻辑继续覆盖换行归一化、Markdown 图片和链接转为可读标签、代码围栏与表格分隔行移除、标题/引用/列表前缀移除、强调与行内代码标记移除、表格竖线替换，以及多余空行折叠。emoji 不参与过滤。

## 错误处理

- Jarvis 空响应、marker 缺失/重复/乱序、原有空章节等情况维持现有失败路径。
- 新增“章节清理后为空”的校验，记录不包含正文和敏感信息的错误类别，并向全部本次订阅者发送既有总结失败消息。
- 不因格式清理失败而发送部分章节，避免用户收到结构不完整的每日总结。

## 测试与验证

新增或更新单元测试，覆盖：

- 总结提示词明确禁止 Markdown，并允许 emoji 强调重点。
- Markdown 标题、列表、强调、代码、引用、表格和链接被转换为 QQ 普通文本。
- emoji、普通中文标点和自然段被保留。
- 四章均在发送格式化前完成清理。
- 任意章节清理后为空时返回错误。
- 既有章节顺序、章节标题和消息长度限制不回归。

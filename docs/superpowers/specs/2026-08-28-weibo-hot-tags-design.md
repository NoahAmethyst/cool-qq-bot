# 微博热搜标签与 QQ 报告设计

## 目标

同步 Spider gRPC 新增的 `WeiboHot.tags` 字段，并在 QQ 的微博热搜报告中以易扫读的纯文本形式展示热搜标签。

## 数据契约

- 在 `protocol/spider.proto` 的 `WeiboHot` 中保留现有字段号，新增 `repeated string tags = 5;`。
- 重新生成 Go protobuf/gRPC bindings，使 Spider 客户端可通过 `GetTags()` 读取标签。
- `util/top_list.WeiboHot` 新增 `Tags []string`，由 Spider 响应复制而来；该字段会自然进入现有每日热搜记录，以便 `#微博 <排名>` 显示与实时榜单一致的标签。

## QQ 纯文本格式

完整榜单使用 QQ 兼容的装饰字符、时间和序号，不使用 Markdown。每一项保持单行：

```text
╭─ 微博实时热搜
│ 2026-08-28 10:30
╰────────────
01. 孙宇晨说长文写了十几个小时  🔥
02. 四川地震  👀
────────────
发送 #微博 1,2,3 获取详情
```

单条详情保留标题、可选标签和链接。已知标签仅显示 Emoji；未知标签保持原样，避免丢失 Spider 新增的语义。多个标签用空格连接。

| 标签规则 | QQ 展示 |
| --- | --- |
| `当前爆词` | `🔥` |
| `好友正在看` | `👀` |
| `上午霸榜` | `🌅` |
| `凌晨霸榜` | `🌙` |
| 包含 `登顶` | `👑` |
| 其他标签 | 原始标签文字 |

## 错误处理与兼容性

- 空标签数组不显示任何标签，不产生多余空格。
- 旧 Spider 服务未提供字段时，protobuf 默认返回空数组，维持现有行为。
- 未知标签不映射 Emoji，直接显示原文。

## 验证

- 单元测试覆盖空标签、每个已知映射类别、未知标签、多标签及完整榜单/单条消息格式。
- 先运行相关 Go 包测试，再运行 `go test ./...` 和 `go vet ./...`；生成代码后确认 `go build ./...` 可通过。
